# Report：实验 4，去重后用同样的预算放进更多证据

*Bowen · 2026-10-15 · 对应 plan v2 §7 实验 4*

## 一句话结论

**把 trie 写成文本（T）后，把 cap 从 8 提到 30，路径 token 只是原来 cap=8 基线的 1.13–1.14 倍，Hit 却提高 2–6 个点；准确率与 M0 cap=30 持平，而 M0 cap=30 要用 2.8–3.2 倍的 token。** 用 mask 实现的 trie（M2）在 cap=30 下比 cap=8 掉得更多。其中 M2-par（并行位置）崩得很厉害，这正是 plan 预先列出的"并行窗口太多"风险。

## 设置

和实验 2 相同（引擎、500 题子集、greedy 16 token），只是 cap 改为 30，路径来自 `precomputed_paths_v2`；在 RoG 和 Llama-2-7B × CWQ/WEB 上跑 M0、T、M2-hyb、M2-par。v2 中每个 query 平均有 21.6 条（CWQ）和 17.4 条（WEB）路径，上限 30 条。

## 结果一：都以 M0 cap=8 为基线，比较代价与准确率

ΔHit 括号内为变好/变差题数；token 倍数 = 路径区 token / M0 cap=8 的路径区 token。

| 模型 / 数据集 | M0 cap8 | T cap8 | M0 cap30 | **T cap30** | M2-hyb cap30 | M2-par cap30 |
|---|---|---|---|---|---|---|
| RoG CWQ | 0.508（1.00×） | +0.8（0.45×） | +6.8*（3.16×） | **+6.4*（1.14×）** | −1.8（0.99×） | −9.2*（0.99×） |
| RoG WEB | 0.754（1.00×） | +0.6（0.50×） | +4.4*（2.82×） | **+4.8*（1.13×）** | −2.8（0.96×） | −9.8*（0.96×） |
| Llama-2 CWQ | 0.406（1.00×） | −0.6（0.45×） | +5.2*（3.16×） | **+3.4*（1.14×）** | −2.6（0.99×） | −6.8*（0.99×） |
| Llama-2 WEB | 0.678（1.00×） | +0.4（0.50×） | +0.0（2.82×） | **+2.0（1.13×）** | −2.4（0.96×） | −7.6*（0.96×） |

\* 表示 McNemar p<0.05。原始数字见 `outputs/exp4/cross_cap.txt`。

## 结果二：在 cap=30 内部，以 M0 cap=30 为基线

| 模型 / 数据集 | M0 | T | M2-hyb | M2-par | 路径 token：M0 / T / M2 |
|---|---|---|---|---|---|
| RoG CWQ | 0.576 | −0.4 | −8.6* | −16.0* | 702 / 254 / 219 |
| RoG WEB | 0.798 | +0.4 | −7.2* | −14.2* | 467 / 187 / 160 |
| Llama-2 CWQ | 0.458 | −1.8 | −7.8* | −12.0* | 702 / 254 / 219 |
| Llama-2 WEB | 0.678 | +2.0 | −2.4 | −7.6* | 467 / 187 / 160 |

按路径数分桶：所有条件在 ≤4 条路径时几乎一样；差距全部出现在 ≥5 条路径的桶里。以 RoG CWQ 为例，≥5 条路径时 M0 0.572、T 0.565、M2-hyb 0.470、M2-par 0.391。

## 结论

1. **证据越多越好，而 T 让这件事变得便宜。** cap 从 8 提到 30，M0 提高 0–7 个点；T 拿到同样的提升，路径 token 却只比 cap=8 基线多 13–14%，比 M0 cap=30 少 64%（CWQ）和 60%（WEB）。这是目前最直接、最容易落地的结果：只改 prompt 的序列化方式，不需要改模型，也不需要改 kernel。
2. **cap=30 时，T 仍然和 M0 持平**（|Δ| ≤ 2，不显著），说明文本 trie 在路径多的情况下依然成立。
3. **M2 在路径变多后损失变大。** M2-hyb 相对 M0 的损失从 cap=8 时的 3–7 个点扩大到 2–9 个点；M2-par 从 2–7 个点扩大到 8–16 个点。并行位置让几十条路径共用同一段位置编号，问题 token 很难分辨这些路径，正是 plan §3.4 预先写下的风险。**今后默认用 hyb，不再使用 par。**
4. **在相同 token 预算下**，M2-hyb cap=30 与 M0 cap=8 打平（Δ −1.8 到 −2.8，不显著）：花同样的 token，mask 方案的准确率基本不变，同时还有跨 query 复用和 prefill 并行。但它明显不如 T cap=30。mask 方案要有竞争力，就必须先把跨路径整合补回来（实验 3）。

## 结果三：T 配合现成的前缀缓存，能拿到多少跨 query 复用（CPU 统计）

`experiments/exp4/prefix_cache_stats.py`，Llama-2 tokenizer。表中是"省掉的路径区 prefill"的比例，都相对 M0 无缓存而言；preamble 不计入，因为所有方案都会缓存它。radix 表示 RadixAttention 式的前缀缓存（vLLM/SGLang 现成就有）。

| 数据集 / cap | batch | flat + radix | T | **T + radix** | M2 节点级（query 内 + 跨 query） |
|---|---|---|---|---|---|
| CWQ / 8 | random 64 | 0.023 | 0.548 | **0.559** | 0.611 |
| CWQ / 8 | topical 512 | 0.309 | 0.548 | **0.691** | 0.757 |
| CWQ / 30 | random 64 | 0.018 | 0.643 | **0.649** | 0.704 |
| CWQ / 30 | topical 512 | 0.269 | 0.643 | **0.744** | 0.825 |
| WEB / 8 | random 64 | 0.008 | 0.492 | **0.496** | 0.557 |
| WEB / 30 | topical 512 | 0.107 | 0.594 | **0.636** | 0.702 |

完整表见 `outputs/exp4/prefix_cache_stats.txt`。

**结论：** T 本身就拿到了绝大部分节省。再配合现成的前缀缓存，与 M2 节点级复用的差距只剩 **5–8 个百分点**的路径 token。而 M2 在准确率上要付出 2–9 个点（实验 2 和本实验）。所以只看 prefill token 节省，在当前的准确率下，"T + 现成前缀缓存"严格优于 M2。M2 只剩两个独有的系统价值：prefill 时路径之间的 attention 可以并行（计算比 0.05–0.17）；检索与 prefill 可以流水线。这两点在短上下文（这里每题约 200–700 个路径 token）下的收益有限，需要端到端测量才能确认。

## 对研究路线的影响

- **T 应该成为主线的第一个贡献**："检索结构决定 prompt 结构"，在相同 token 预算下 +3 到 +6 个点，或者在相同准确率下省 60% 的 token。它直接对应 proposal 的 T1.1（IR 中的 composition relationships）和 T2.3。
- **mask 方案（M2）的定位**取决于实验 3（top-ℓ、sibling 组、LoRA）能补回多少。按结果三，即便准确率补回来了，它相对"T + 现成前缀缓存"的 token 节省也只多 5–8 个百分点。所以 M2 要成为独立贡献，需要拿出 T 做不到的东西，比如更长的上下文（让 attention 的平方项占主导），或者检索与 prefill 的流水线带来的 TTFT 收益。否则就应该把 M2 降为分析性结果（"为什么独立编码会掉点、去重为什么有帮助"）。
