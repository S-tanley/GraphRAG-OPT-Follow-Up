# Report：箭头重算实验（"词典式"KV + 只在上下文里重算连接 token）

*Bowen · 2026-10-16 · 想法来自 Bowen（2026-10-16 讨论）*

## 一句话结论

**"关系信息汇聚在箭头上"这一假设没有得到支持。** 只重算箭头和换行（约 13% 的路径 token），效果和"什么都不重算"、"随机重算同样数量的 token"没有区别；三者相对 M0 都掉 6–15 个点，比 M2（trie mask）掉得更多，也不比 CacheBlend 在相近预算下更好。注意力诊断给出了同样的结论：在正常读法下，问题 token 落在箭头上的注意力远低于箭头所占的 token 比例。唯一的正面信号是：在 Llama-2 上，额外重算每个实体的最后一个 token（共约 22%）能补回大约一半损失，但在 RoG 上无效。补充实验还表明，反过来**只把箭头换成缓存 KV、其余照常**也会明显掉点（最多 −14），所以箭头同样不能无损复用。

## 想法和设计

- **"词典式"KV**：每个实体、每个关系各自作为一段，放在固定指令后面单独编码（位置从指令之后开始编号）。这样它们的 KV 和出现在哪题、哪个位置、旁边有什么都无关，可以全局复用。
- **重算的 token**：在上下文里正常计算，能看见前面全部内容，位置用顺序编号。
- **问题和答案**：照常能看见全部内容。
- 实现上给引擎增加了"按行选择位置"的功能（`ctx_rows`）：被重算的行用顺序位置，缓存的片段用片段内的局部位置。代码在 `experiments/common/{masked_engine,conditions}.py`。

| 条件 | 重算哪些 token | 作用 |
|---|---|---|
| A-pieces | 不重算 | 下限 |
| **A-arrow** | 箭头 `▁->` 和行尾换行 | 要验证的方案 |
| A-rand | 随机挑选，数量与 A-arrow 相同 | 对照：检验箭头是否特殊 |
| A-arrowlast | 箭头、换行，再加每个实体的最后一个 token | 检验实体 token 是否关键 |

token 的类别直接用分词器的字符偏移来判定，不改变 M0 的切法。例如：`▁New/ent ▁York/ent ▁->/arrow ▁location/rel … ▁->/arrow ▁Brook/ent lyn/ent ▁Bridge/ent <0x0A>/nl`。

**正确性检查**（`experiments/arrow/gate.py`）：

- A-all（所有路径 token 都重算）和 M0 的预测 60/60 完全一致；
- 同一个实体或关系片段出现在不同位置时，KV 最大差 1.66e-2（相当于 fp16 的舍入误差，76 组比较）。

**设置**：RoG 和 Llama-2-7B × CWQ/WEB，各 500 题，每题最多 8 条路径，与实验 2 相同。RoG 跑在 GPU0，Llama-2 跑在 GPU1。

## 结果一：准确率（ΔHit 相对 M0；* 表示 p<0.05）

| 条件 | 重算比例 | RoG CWQ | RoG WEB | Llama-2 CWQ | Llama-2 WEB |
|---|---|---|---|---|---|
| M0（Hit） | 100% | 0.508 | 0.754 | 0.406 | 0.678 |
| M2-hyb（参照） | 0% | −3.4* | −3.0* | −7.2* | −3.2 |
| M1-hyb（GraphRAG-Opt 全部复用） | 0% | −6.8* | −4.4* | −12.4* | −9.8* |
| A-pieces | 0% | −6.2* | −8.6* | −11.6* | −15.2* |
| A-rand | 13–14% | −6.6* | −10.0* | −13.6* | −14.6* |
| **A-arrow** | 13–14% | **−7.0*** | **−8.0*** | **−11.2*** | **−14.0*** |
| A-arrowlast | 22% | −7.8* | −7.4* | −5.6* | −9.0* |
| CacheBlend 15%（GraphRAG-Opt ablation） | 15% | −5.6 | −4.6 | −9.0 | −7.4 |
| CacheBlend 30%（GraphRAG-Opt ablation） | 30% | −4.0 | −4.2 | −7.8 | −6.0 |

CacheBlend 的数字来自 GraphRAG-Opt 自己的 ablation：同一批 500 题，引擎不同，但完整计算的结果和我们的 M0 只差一题，可以作为近似参照。

## 结果二：注意力诊断（正常读法 M0，CWQ 前 100 题，32 层平均）

表中是问题 token 的注意力落在各类 token 上的比例，括号里是"注意力占比 ÷ token 占比"：大于 1 表示受到的关注多于平均水平，小于 1 表示少于平均水平。

| 类别 | token 占比（RoG） | RoG：问题 token 的注意力 | Llama-2：问题 token 的注意力 |
|---|---|---|---|
| 指令（含开头的 attention sink） | 19.5% | 72.7%（3.7×） | 73.5%（3.0×） |
| 实体 | 29.1% | 6.9%（0.24×） | 5.8%（0.21×） |
| 关系 | 40.5% | 4.9%（0.12×） | 4.7%（0.12×） |
| **箭头** | 8.3% | **1.2%（0.15×）** | **1.3%（0.16×）** |
| 换行 | 2.6% | 1.4%（0.55×） | 1.4%（0.58×） |

分层来看：最后一个问题 token（负责生成答案第一个 token）在第 16–23 层对实体的注意力最高，约 0.11；对箭头的注意力在所有层段都 ≤ 2%。

## 结论

1. **箭头并不特殊。** A-arrow 和 A-rand、A-pieces 的差距都在噪声范围内；注意力诊断也显示，问题 token 几乎不看箭头（只有平均水平的 0.15 倍）。所以"关系信息汇聚在箭头上"这个假设，在 RoG 和 Llama-2 上都不成立。
2. **拆得更碎反而更差。** A-pieces 把实体和关系拆开、彼此独立编码，比 M2（整条前缀一起编码）多掉 3–12 个点。实体单独编码时"不知道自己是从哪个关系来的"，这部分信息无法靠少量重算补回。这和实验 3 的结论一致：整合是分散在很多 token、很多层上完成的。
3. **在相近的重算预算下，A-arrow 也不比 CacheBlend 好**（例如 RoG CWQ：−7.0 vs CacheBlend 15% 的 −5.6）。所以"由结构决定重算哪些 token"至少在箭头这个选法上，没有胜过按偏差挑选。
4. **唯一的正面信号是实体 token。** 在 Llama-2 上，额外重算实体的最后一个 token，CWQ 从 −11.2 回升到 −5.6，WEB 从 −14.0 回升到 −9.0；但 RoG 上没有改善。再结合诊断结果（答案 token 在中层更关注实体），说明如果要挑"核心 token"，实体比箭头更有希望。但要把损失降到噪声以内，单靠这一招远远不够。
5. **换行 token 受到的关注相对较多**（0.55×，是其他路径 token 的 3–4 倍），可能起到"行级小结"的作用。不过在 A-arrow 里换行也一起重算了，仍然没有帮助。

## 补充实验：箭头能否"无压力"复用（A-noarrow）

**问题**：既然箭头既不汇聚信息、问题 token 也几乎不看它，那么把箭头换成缓存的、和上下文无关的 KV（只看指令和它自己），其余所有 token 照常正常读，是否不会掉点？

**结果**（`outputs/arrow/noarrow_compare.txt`；缓存部分约占路径 token 的 10%）：

| | M0 | A-noarrow | ΔHit | 变好/变差 | p | 预测完全相同 |
|---|---|---|---|---|---|---|
| RoG CWQ | 0.508 | 0.508 | 0.0 | 23/23 | 1.00 | 350/500 |
| RoG WEB | 0.754 | 0.720 | −3.4* | 17/34 | 0.02 | 346/500 |
| Llama-2 CWQ | 0.406 | 0.320 | −8.6* | 26/69 | <0.001 | 242/500 |
| Llama-2 WEB | 0.678 | 0.538 | −14.0* | 11/81 | <0.001 | 274/500 |

**结论**：**箭头不能无压力复用。** 只动 10% 的 token，就有 30–52% 的题答案发生变化，Llama-2 最多掉 14 个点。这说明：

- 问题 token 不看箭头，**不代表箭头不重要**。箭头是路径里其他 token（关系、实体）读取上下文的必经节点。把它换成和上下文无关的表示，会通过后续 token 的计算逐层传播出去。
- 注意力诊断只测了"问题看什么"，没有测"路径 token 之间看什么"，所以不能据此推断哪些 token 可以安全复用。这是这次诊断方法的局限。
- 对整个"挑一部分 token 复用"思路的启示是：**某个 token 能否安全复用，要看它对所有后续 token 的影响，而不只是对问题 token 的影响**。

## 对研究路线的影响

- 这个结果进一步支持了实验 3 的判断：在 KG 路径上，"复用 + 少量 token 修补"（不管按偏差、按位置还是按结构挑 token）都补不回损失。要么不切断路径之间的联系（T），要么通过训练让模型适应（LoRA-M2）。
- 如果之后还想继续"核心 token"的思路，更值得试的是：把实体 token 作为重算对象，并配合 LoRA 训练；或者引入专门的汇总 token（比如每行末尾加一个可训练的 token）。这两种都需要训练，不再是免训练方法。
